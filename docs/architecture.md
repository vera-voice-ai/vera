# Вера 0.3 · архитектура

Вера 0.3 — нативное macOS-приложение (SwiftUI), которое показывает работу Hermes Agent
и служит местом, где мы дорабатываем Hermes под себя. Визуальный язык — из Веры 2
(`../vera-v2/prototype/App`): тёмная доска, пунктирные контуры модулей, цветная точка домена,
моноширинные подписи.

## Принцип: мозг один — Hermes, Вера — обвязка

Вера ничего не решает и не вызывает модели сама. Единственный мозг — агентный цикл Hermes. Наше — то, что вокруг:

| Наше | Что делает | Почему это не «мозг» |
|---|---|---|
| Разговор (плитка на схеме, история и настройка провайдера — карточками) | показывают и передают | только интерфейс |
| Голос | микрофон → текст (уши в коробке: Silero VAD + GigaAM / T-one), текст ответа → речь | распознавание и озвучка, без смысла |
| Адаптер | запуск Hermes, шлюз, сообщения и /команды, вопросы агента по окнам | транспорт |
| Пульс + `vera-pulse` | наблюдение и счётчики | только записывает |
| `vera-setup` | модель по умолчанию тем же кодом, что Desktop | настройка |
| `vera-ears` | распознаватель `gigaam` для голосовых (Telegram и др.): Hermes сам скачивает голосовое и зовёт его, плагин запускает `Vera --transcribe` (VAD + GigaAM из коробки, офлайн); путь к Вере — `VERA_EARS_BIN` в окружении шлюза | уши |
| `vera-phone` | инструменты Hermes для навигатора и плеера iPhone: `phone_route` (место → маршрут, `start` — вести), `phone_route_status`, `phone_route_stop`, `phone_music_play` / `_control` / `_status`; запрос — файл в `phone-bridge/commands`, Вера (`PhoneNavBridge`) шлёт его телефону (`navigate` / `music` → `navResult`, состояние `nav` → `nav.json`); подробно — [phone.md](phone.md) | связь с телефоном |
| `vera-context` | каждому каналу — описание всех трёх и подробно своего (раздел системного промпта; старым сессиям и сессиям со старым текстом — один раз в ход, по дайджесту текста); канал — `client` сессии (`vera-mac`/`vera-phone`), закреплённые сессии Веры, платформа `telegram` | разговор |
| `vera-browser` | инструмент `mac_browser` (open / show / hide / close / status): окно «Браузер Веры» на Маке — Chromium Hermes с постоянным профилем и темой Веры, порт DevTools 9333 только на loopback; Hermes работает в нём через `browser.cdp_url` (Вера прописывает при запуске; закрытое окно хук `pre_tool_call` открывает перед `browser_exec`/`browser_cdp`/`browser_dialog` — иначе модель запускала чужой браузер), владелец видит страницы и сам решает капчу и жмёт последнюю кнопку; колонка «Браузер» в «Сенсорах MacBook» | руки на Маке |

Явная механика без интеллекта: конец фразы — 1,4 с тишины; перебивание — замолчать и `session.interrupt`;
короткое «да/нет» голосом отвечает на открытый вопрос о разрешении (список слов, `VoiceApproval`).
Идеи Веры 2 с собственным «быстрым мозгом» (внимание на DeepSeek, рефлексы с моделью) сюда не переносятся;
уши, «кто говорит» и сцена — только как факты и контекст для хода Hermes.

## Главное решение: Hermes внутри Веры, без форка

Hermes Agent — Python-проект почти на миллион строк. Порт на Swift (`../hermes-swift`) для Веры 0.3 не нужен.
Вера несёт в себе официальный пакет Hermes (последний stable, собранный его же `pm bundle`) и ничего не берёт
с машины — подробно в [hermes-updates.md](hermes-updates.md).

```
┌──────────────────────────── Vera03.app ────────────────────────────┐
│  Vera (SwiftUI)        одно окно — схема                            │
│  HermesBridge          HermesRuntime (пакет, данные, окружение),    │
│                        Bootstrap, GatewayAttach, GatewayClient,     │
│                        PulseFeed, LockStatus                        │
│  Resources/hermes      Hermes v0.23.3: CPython + зависимости + код  │
│  Resources/plugins     vera-pulse, -setup, -ears, -phone, -context│
└───────────────┬──────────────────────────────────▲──────────────────┘
   запускает     │ WebSocket hermes-gateway-v1      │ JSONL
   (свой HOME)   ▼                                  │
┌──── шлюз Hermes Веры · данные в ~/Library/Application Support/Vera03/hermes ───┐
│  сессии · модель · инструменты · плагин vera-pulse → hermes/vera-pulse/*.jsonl  │
└─────────────────────────────────────────────────────────────────────────────────┘
```

### Два канала от Hermes к Вере

1. **Шлюз (gateway)** — тот же механизм, через который к Hermes подключаются его TUI, Desktop и дашборд,
   но шлюз свой, из пакета Веры. `hermes gateway attach --json --recover` (под окружением Веры) поднимает его,
   если он не запущен, и возвращает `url` (`ws://127.0.0.1:<port>/api/ws`),
   `protocols` (подпротоколы WebSocket: `hermes-gateway-v1` и одноразовый тикет) и
   `endpoint` (instance, supervisor, capabilities, `code_sha`). Тикет — секрет, живёт 30 с,
   нигде не логируется. После подключения сервер шлёт событие `gateway.ready`;
   клиент держит связь `gateway.ping` и может вызывать канонические методы
   (`runtime.describe`, `session.info`, `session.stats`, …).
   Вера **не** объявляет `client.capabilities {server_requests: true}`: она наблюдатель
   и не отвечает на вопросы агента, поэтому Hermes никогда не ждёт её ответа.
2. **Плагин `vera-pulse`** — подписан на хуки жизненного цикла Hermes
   (сессии, запросы к модели, вызовы инструментов, сабагенты, ожидание человека, компакция)
   и пишет очищенные события в
   `~/Library/Application Support/Vera03/hermes/vera-pulse/<yyyy-MM-dd>.jsonl`.
   Аргументы инструментов, тексты сообщений и ответы модели **не** пишутся — только имена,
   идентификаторы, длительности, статусы, счётчики токенов. Плагин также отдаёт последние
   события по RPC `plugin.vera-pulse.recent`.
   **Пульс живьём:** каждая строка уходит ещё и событием `plugin.vera-pulse.event` (`broadcast_plugin_event`);
   адаптер получает его по шлюзу и кладёт в «Пульс» сразу (линия «адаптер → пульс (живьём)»). Журнал на диске —
   история (неделя, события до старта Веры) и запасной путь, когда шлюз не отдаёт события; повторы режутся по `id`.

### Сессии Hermes (вся переписка — «открыть весь чат ↗» в карточке MacBook)

Полноценный клиент сессий Hermes — те же канонические методы шлюза, что у его TUI и Desktop
(`x-canonical-methods` в `apps/shared/src/gateway-contract.openrpc.json`):

| Что | Метод / событие |
|---|---|
| список чатов | `session.list` `scope: live` + `scope: stored` (новый чат попадает в stored только после успешного хода) |
| новый чат | `session.create {source: "gui", cwd: <данные Веры>/workspace}` → снимок с `subscription_id`, `execution_generation` |
| открыть чат | `session.resume {session_id}` → история (`messages`), открытые вопросы (`open_requests`) |
| отправить | `prompt.submit {session_id, text, submission_id}` — `submission_id` (UUID) обязателен: ключ идемпотентности |
| стоп | `session.interrupt {session_id, execution_generation}` |
| уйти из чата | `session.detach {session_id, subscription_id}` |
| поток | события `message.start/delta/complete`, `tool.start/complete`, `thinking.delta`, `status.update`, `agent.print`, `session.usage/info/title`, `request.cancel` |
| вопросы агента | server→client запросы `approval` (`{choice: once/session/always/deny}`) и `clarify` (`{answers, outcome}`), ответ — JSON-RPC response на `srq-…` |

Вера объявляет `client.capabilities {server_requests: true}` и отвечает только на `approval` и `clarify`;
всё остальное (`secret`, `sudo`, хранилище паролей, мосты Desktop) `GatewayClient` сразу отклоняет ошибкой —
агент не ждёт, и Вера никогда не берёт секреты через чат. Вопрос другой сессии тоже отклоняется ошибкой,
а не «запретом» от имени владельца. Свёртка событий в ленту — `HermesBridge/ChatTranscript` (тесты на формах из живого
прогона 2026-11-21).

### Доска: схема «Hermes — цельная плитка, вокруг наше»

Доска рисует ту же схему, что `docs/v3-architectures/simple-v2.png` (`OrganismBoard`): наши Разговор, Уши, Голос, Адаптер и Пульс,
цельная плитка Hermes и внешний провайдер. Рабочего Hermes владельца на доске нет: Вера с ним не связана. В плитках только живое:
Окна — основная сессия, её состояние, последнее твоё сообщение, число разговоров у Hermes; Голос — состояние, что
услышала и что сказала; Адаптер — шлюз, последний вызов, ждёт ли агент ответа; Пульс — счётчики и последнее событие;
Память — замер `state.db`, `memories/`, `skills/`, логов и журнала (`DataUsage`); Провайдер — модель, запросы, ошибки,
средняя задержка и лимиты плана.

- **Расход и нагрузка — справа в шапке, как в Вере 2.** Лимиты плана текущего провайдера (OpenCode Go: 5 ч / неделя /
  месяц, зелёный < 60 %, жёлтый < 85 %, красный выше; в подсказке — сброс) читает сам Hermes: RPC нашего плагина
  `plugin.vera-setup.account_usage` вызывает его `fetch_account_usage` для маршрута по умолчанию
  (`resolve_runtime_provider`), раз в 5 минут; ключ остаётся внутри Hermes, наружу — только проценты и время сброса.
  Рядом — память и CPU двух деревьев процессов: Веры (приложение, рот, Smart Turn) и шлюза Hermes (pid из его
  `<HERMES_HOME>/gateway.pid`), раз в 2 с через libproc (`ProcessResources`); в подсказке — по деревьям. Пунктир на схеме (`vera-voice`, прямой голосовой канал) — следующий шаг, на доске помечен «позже».

- **Внутри плитки Hermes** — его стандартные части и наши, вживую из шлюза каждые 30 с (`HermesInventory`):
  шлюз, мозг (модель), руки (`toolsets.list`), навыки (`skills.manage list`), память; плагины (`plugins.list`) —
  наши `vera-*` и стандартные; платформы, cron (`cron.manage list`), MCP (`mcp.servers.list`).
- **Потоки — только реальные** (`FlowMonitor`): вызов шлюза, событие или вопрос агента, сообщение из окна или голосом,
  фраза озвучки, строка журнала пульса, `llm.start/end` (провайдер), `tool.start` (руки). Каждый — точка по своей линии
  и счётчик «за минуту / за 10 минут». Без трафика ничего не бежит (и анимация не тратит процессор).
- **Раскладка схемы:** слева наше — Разговор, Уши, Голос; в центре Адаптер (связь, последние вызовы шлюза, события по
  типам); справа Hermes — внутри него и дорожки журнала vera-pulse за 5 минут (то, что плагин видит изнутри);
  провайдер справа от Hermes по центру; внизу во всю ширину наш Пульс — сводка и «Ход» через всё приложение
  (`PulseState`: журнал, сводка и ходы в одном месте). Рамки «приложение» нет.
- **Линии — к настоящим частям:** адаптер ↔ шлюз Hermes, мозг Hermes ↔ провайдер, мозг → руки (вызов инструмента),
  vera-pulse → Пульс (журнал), Распознавание → адаптер, адаптер → Голос, Разговор → адаптер. Линии «пульс → доска»
  нет: это не поток между частями.
- **Приложение — «Vera v0.3»**, иконка: розовое ядро Hermes с волной голоса в пунктирном зелёном кольце Веры
  (`scripts/make-icon.sh` → `app/Resources/AppIcon.icns`).
- **Версия Hermes** (значок в плитке Hermes; отдельной плитки «Коробка» больше нет): какой Hermes в коробке и
  сходится ли он с замком, есть ли новее stable на GitHub («новее нет» / «есть … ↗») (`UpdateCheck`: один публичный запрос к releases/latest источника из замка, раз в 6 ч, общее имя
  клиента; Вера сама никогда не обновляет — только по процедуре `docs/hermes-updates.md`), версии ушей и голоса из
  `ears.lock.json` — внизу «Сенсоров» и в «Голосе».
- **Hermes на схеме — большая цельная плитка со всем внутри** (`HermesTile`): что он делает сейчас (из пульса), шлюз
  (события за 10 мин), мозг (модель, вызовы за сегодня точками), руки (наборы, самые частые инструменты, ошибки),
  навыки (все точками, наведи — имя и сколько раз), плагины (наши vera-* пунктиром, стандартные сплошные), память
  (размер, записи, рост), платформы (все, писавшие подсвечены), cron, MCP, версия и замок. У каждой части кнопка «▸» —
  её полные подробности рядом (поповер с тем же, что на «Составе»).
- **Плитки не кликаются** — это неочевидно. Нажимаются только явные кнопки: «открыть весь чат ↗» в карточке MacBook,
  «говорить ⌘L», озвучка в «Голосе», карточка движка в «Распознавании», часть «Микрофон» (фоновое слушание, обведена ярче). Подробности всех частей — на
  кнопке «▸» у частей Hermes (поповер с `PartDetail`). Правой панели и вкладок нет.

### Одна вкладка

Всё на одной схеме. Бывшие «Жизнь» и «Состав» влились в неё: созвездие навыков, платформы, плагины, память и рост
данных — в Hermes; подробности любой части Hermes — его «▸»; активность за неделю по часам — в Пульсе рядом с «Ходом»;
вызовы модели за сегодня — в мозге Hermes и у провайдера.

### «Разговор»: одна основная сессия, команды, разрешения, голос — справа на доске

Вера — это само приложение, отдельной «Веры» внутри нет. Разговор (основная сессия Hermes) — карточка MacBook в
«Разговорах» (`MacBookChannelCard`): состояние, последний обмен (реплика Веры появляется, пока она её говорит), сводка сессии
и «партитура» последних 10 минут (`ConversationScore`: ты · думает · руки · голос — шаги ходов из `TurnRecorder`).
Строка «написать или /команда» с подсказками — карточка «Ввод» в «Сенсорах MacBook» (`ChatInputCard`).
Вся переписка — «открыть весь чат ↗» в карточке MacBook; сам чат в основном будет
в Telegram, с Верой — голосом. Вопросы агента — баннером поверх доски (`RequestBanner`). Настройки голоса (фон, порог,
скорость, сравнение движков) — на плитках «Уши» и «Голос».


- **Основная сессия** — одна навсегда: её id в `<данные>/main-session.json`, при старте `session.resume`, первый раз
  `session.create {title: "Вера"}`. Если Hermes при сжатии отдаст новый id, закрепление следует за ним.
- **Команды** — `/…` как в TUI Hermes: подсказки `complete.slash`, выполнение `slash.exec` (запасной путь
  `command.dispatch`), ответ разбирает `SlashOutcome`: `exec/plugin` — вывод, `alias` — другая команда,
  `send/skill` — сообщение агенту, `prefill` — текст в поле ввода (`/undo`).
- **Разрешения и уточнения** — карточки; голосом: Вера проговаривает вопрос, короткое «да» / «нет» отвечает на него
  (`VoiceApproval`). Шлюз отдаёт вопрос только окну, у которого открыта эта сессия; иначе — отказ ошибкой.
- **Голос — наш, в приложении, живой разговор** (уши и рот Веры): ⌘L включает разговор — микрофон открыт, пока его
  не выключить; каждая фраза уходит агенту, как только ты замолчал; говорить можно поверх Веры (перебивание).
  - **Микрофон** — `AVAudioEngine` с системной обработкой голоса (подавление эха), 16 кГц моно. Звук из процесса
    не выходит; наружу только текст.
  - **Конец фразы** — Silero VAD + Smart Turn v3.2: после 0,3 с тишины VAD предлагает конец, Smart Turn по звуку
    (интонация, паузы — не слова) говорит, закончена ли фраза. ≥ 0,5 — фраза уходит сразу; меньше — Вера ждёт
    продолжения ещё до 1,2 с, и если человек продолжил, это одна фраза. Механика, не смысл. Smart Turn — в Python
    голоса (numpy + onnxruntime, `scripts/smart-turn-worker.py`, фильтры Whisper из Веры 2), модель и версии — в
    `ears.lock.json` → `mouth`. Без него в сборке — как раньше, 0,5 с тишины.
  - **Распознавание — двумя движками на выбор** (переключатель в окне, решаем замерами):
    GigaAM v3 с пунктуацией — не потоковый, фраза перечитывается каждые 0,5 с, пока ты говоришь;
    T-one — потоковый, текст растёт каждые ~0,3 с, без пунктуации. Слушает один движок; флажок «сравнивать с … в
    тени» (по умолчанию выключен — удваивает работу ушей) даёт второму движку читать **те же фразы**: основной
    `Listener` пересказывает тени начало (с тем же предзахватом), звук и конец (`Listener.Mirror` → `ShadowReader`),
    своего VAD у тени нет. В журнал тень пишет только счётчики с пометкой `shadow`, агенту — ничего.
  - **Smart Turn асинхронно:** спрашивается на тишине в своей очереди, микрофон не ждёт; ответ возвращается в очередь
    ушей, поздний ответ к закрытой фразе отбрасывается (поколение фразы). Таймаут — те же 1,2 с: если человек
    продолжил и снова замолчал, а ответа нет, фраза всё равно закроется.
  - **Всё в коробке**: библиотека sherpa-onnx (C API, `dlopen` из бандла — Вера собирается и тестируется без неё) и
    модели лежат в `Vera03.app/Contents/Resources/ears`; версии и sha256 — в `ears.lock.json`, сборка —
    `scripts/build-ears.sh` (кэш `~/.vera03/downloads`, выход `~/.vera03/build/ears`). Ни Siri, ни Диктовки, ни Python.
  - **Микрофон — две дорожки на одном потоке, у каждой своя кнопка** (часть «Микрофон» в «Сенсорах»).
    **Запись** (включена по умолчанию, состояние помнится, стартует с Верой): микрофон открыт всегда, всё распознанное
    ложится в журнал `ears/background-YYYY-MM-DD.jsonl` (текст, длина, громкость; только на этой машине) и агенту не
    уходит. Микрофон — **обычный вход без системной обработки голоса**: открывается без сбоя звука, ничего не
    приглушает, созвоны в Zoom и браузере не трогает. Поэтому пока Вера говорит (и 0,5 с после), уши не слушают —
    иначе она слышала бы себя; перебивают её кнопкой или ⌘L, не голосом (системное подавление эха macOS при
    включении перестраивает звуковое устройство — секунда тишины у всего Мака — и приглушает чужой звук; провести её
    голос через движок микрофона на macOS нельзя: с обработкой у выхода движка 0 каналов). **Вера** (⌘L):
    неактивна — ничего не отправляет и ждёт ключевую фразу («Привет, Вера, …», `WakePhrase` — явное совпадение первого слова
    текста GigaAM, без модели, громкость не важна: у короткого «Вера» медиана уровня фразы — тишина); активна — каждая фраза уходит агенту (и по-прежнему пишется). Ключевая
    фраза делает её активной: остаток сразу уходит агенту, на одно «Привет, Вера» — «Слушаю.». Через 30 с без речи, ответа и
    хода — снова неактивна. С выключенной записью микрофон открыт только пока Вера активна. Порог настраивается ползунком на «Ушах»
    (по умолчанию −45 дБ), рядом — текущий уровень и громкость последней фразы, чтобы подобрать его по себе.
    В фоне перебить Веру может только звук громче порога. Порог — абсолютный: в Вере 2 «над фоном» ломалось, когда
    подавление эха глушит тишину в ноль, а жёсткий порог в разговоре отрезал тихие настоящие просьбы — поэтому
    в режиме ⌘L порога нет. Громкость и «ушла / нет» пишутся в журнал ушей.
  - **Музыка внутри Веры — одна медиатека с iPhone** (`app/Sources/VeraMusic`: трек, «Моё любимое», исполнители,
    альбомы, поиск, очередь «откуда включил», чтение тегов и формата; новые функции музыки — сюда, сразу для обоих).
    Источник один: что Hermes скачивает в `workspace/soulseek` (каталог `каталог.json`, статус «скачано», файлы
    `музыка/`) — Мак читает на месте (`MusicSources.soulseek`), телефону уходит зеркалом с `library.json`
    (`scripts/phone-music-sync.sh`, `MusicSources.folder`). На Маке: колонка «Музыка» в «Ответ · голос» и окно
    «Медиатека Веры» (`MusicWindow`, снимок `--snapshot-music`); играет сама Вера (`MacMusic`), поэтому громкость
    ведёт она: ждёт «Привет, Вера» — 100%, активна и слушает — 15%, говорит — 10% (плавно). Чужой звук Мака не трогается.
  - **iPhone — так же, две дорожки на одном микрофоне** (`Conversation`, экран «Вера»): «Запись» (по умолчанию выключена —
    батарея; пишет в `Documents/Sensors/<день>/background.jsonl`, дома уезжает на Мак с журналом активности) и «Вера»
    (ждёт «Привет, Вера, …» — `WakePhrase` из общего `VeraListen`; активна — уходит всё; «Слушаю.»; 30 с тишины — снова ждёт;
    кнопка «Вера» и кнопка гарнитуры переключают). Подавление эха на iPhone работает (голос, музыка и микрофон — один
    движок `AudioRig`), поэтому перебивать голосом можно. Музыка при открытом микрофоне играет через этот движок
    (эхо вычитается — «Привет, Вера» не ловится из песен; громкость ведёт Вера), при закрытом — сама, трек переходит на том же месте.
  - **Звук живьём:** в «Микрофоне» (Сенсоры) — спектрограмма за 5 с, 0–8 кГц (`Spectrum`: окно 32 мс, столбец каждые
    20 мс, 64 полосы, Accelerate — API самой macOS), под ней розовая черта там, где VAD слышит речь; в «Голосе» — кольцо
    того, что говорит Вера (контур каждого предложения Silero, в темпе проигрывания). Только настоящие отсчёты.
  - **«Ход» — куда уходит время** (внутри плитки «Пульс» внизу схемы; Пульс = наблюдение: сводка журнала, ход, дорожки): один ход основной сессии дорожками во времени — фраза и дочитывание
    (уши), шлюз (`prompt.submit`), модель и руки (vera-pulse со своими отметками времени, только сессия разговора),
    текст ответа (события шлюза), голос (рот: первое предложение зазвучало → тишина). Сверху итог: всего, до первого
    слова, модель × N, инструменты; справа — последние ходы, клик показывает любой. Собирает `TurnRecorder`
    (HermesBridge, с тестами); проверочный образец рисунка — только в `--snapshot-flows`.
  - **Озвучка читает всё, что в ответах:** перед Silero текст идёт через `SpeechText` (SileroVoice, общий с телефоном, с тестами) —
    числа словами (до 6 цифр, длиннее — по цифрам), дроби, время, «+ − % ° = / & №», латиница по звучанию (короткие
    аббревиатуры — по буквам). Выбрано из нормалайзера Веры 1/2 только нужное, без новых пакетов. Промежуточные
    сообщения агента (`message.interim`: «Проверяю погоду…») тоже озвучиваются. На экране — исходный текст.
  - **«Уши» — как «Органы чувств» Веры 2:** карточка микрофона (круглая кнопка фона, подавление эха, уровень, волна,
    порог) и «Анализаторы» столбиком (Silero VAD, GigaAM v3, T-one: последний результат и цифры); звук идёт к ним
    шиной слева, фраза уходит в адаптер из выбранного распознавания.
  - **На схеме голос — две плитки:** «Уши» (части Микрофон → VAD и → Распознавание, волна, «фон: вкл/выкл», уровень
    против порога с ползунком — розовое сейчас, белая черта порог, зелёная последняя фраза, сравнение GigaAM и T-one,
    «говорить ⌘L», движок) и «Голос» (волна Silero, «сказала», озвучка вкл/выкл, скорость). Фраза идёт из «Ушей» в
    адаптер, ответ — из адаптера в «Голос».
  - **Раскладка** (холст 2640×1460, двигается трекпадом и на Sidecar; ширина — ради воздуха, не ради размера),
    слева направо: «Голос» над «Сенсорами MacBook» (ответ разговора приходит в него стрелкой) → «Разговоры» → адаптер → Vera-core (плитка Hermes:
    «коробка Hermes-agent с плагинами для Vera») → снаружи провайдер и бот Telegram. Внизу «Пульс», в правом нижнем
    углу — легенда (`BoardLegend`, цвета из `FlowLayer.color`). Линии считаются от рамок плиток (`OrganismBoard.paths`).
    Отдельной «Коробки» нет: версии стоят у своих частей — Hermes, замок и «есть ли новее stable» в значке Vera-core
    (в подсказке — как обновить), версии ушей внизу «Сенсоров», голоса — в «Голосе».
  - **Разговоры** (`ConversationsTile`) — канал = одна сессия Hermes, новых сессий из интерфейса не создаём.
    *MacBook* — основная сессия: последний обмен, уведомления Hermes (строки `user` с `display_kind`, например итог
    фонового процесса, — это не реплика человека), вопросы агента, партитура. Ввод — «Ввод» в «Сенсорах»; фраза и
    набранный текст идут в разговор, разговор ↔ адаптер (`prompt.submit`, события хода), ответ → «Голос».
    *Telegram* — сессия самого Hermes: бот снаружи шлёт сообщения прямо в платформы Vera-core, мимо адаптера, и Hermes
    отвечает сам. Карточка — наша (розовая, пунктир): переписку читает адаптер методом `session.transcript` (чтение
    сохранённой сессии без подключения, последние 16 строк) сразу после живой строки пульса этой сессии (пачка строк —
    одно чтение через 0,5 с) и вместе с инвентарём раз в 30 с; линия «адаптер → Telegram». Из пульса — состояние (думает,
    ждёт ответа человека) и последний запрос; домашний ли это канал Hermes — `/sethome`, читает
    `plugin.vera-setup.home_channels` через `gateway.config.load_gateway_config`, без id чата. В журнал пульса слова
    по-прежнему не попадают. *Телефон* — позже, своя сессия через адаптер.
  - **Пульс · запросы** — до 10 последних запросов ко всем каналам (MacBook, Telegram, cron) на одной оси времени
    (`RequestLog` из журнала vera-pulse по id хода Hermes): вызовы модели и инструментов, у MacBook — ещё фраза и
    голос ответа; справа итог — «ответ ✓», «идёт», «прерван», «ошибка» или «оборван» (конца хода в журнале нет, а
    сессия уже пошла дальше — так режет ход перезапуск шлюза). Видно, что первый запрос получил ответ, пока второй
    ещё идёт (Hermes ставит запрос в занятую сессию в очередь или вливает в текущий ход). Под ними — подробный «Ход»
    последнего разговора и неделя по часам.
  - **Сенсоры MacBook** (эскиз `docs/v3-architectures/senses.png`) — два входа: «Микрофон» с ухом и «Ввод» (строка
    запроса, «⌘V вставить», «/ команда»; переписки здесь нет — «открыть весь чат ↗» в карточке MacBook). Под ними
    анализаторы по пути звука: Silero VAD → на тишине Smart Turn; параллельно микрофон → «Распознавание» (одна
    карточка, движок выбирается внутри, флажок сравнения); VAD и Smart Turn шлют распознаванию «началась / закрыта»;
    CAM++ выключен, линии нет. Над сенсорами — «Ответ · голос»: на какую реплику ответ, текст ответа вместе с голосом
    (сказанное ярко, впереди бледно), озвучка, скорость, «замолчать».
    Telegram — стандартная платформа Hermes (сплошная оранжевая рамка): его сообщения идут прямо в Hermes, линия на
    схеме — в «Платформы», мимо нашего адаптера. Плитка показывает состояние платформы из записи шлюза
    (`gateway_state.json` → `platforms.telegram`, обновляется по `platforms.changed`), разговоры из Telegram (пульс) и
    кнопку «⚙ подключить»: владелец вставляет токен бота от @BotFather (отдельного, не рабочего) и, если нужно, id
    разрешённых людей; `vera-setup` сохраняет их функциями самого Hermes (`save_env_value_secure`) в его `.env`, Вера
    токен не хранит и не показывает; шлюз перезапускается. Telegram работает, пока запущена Вера (шлюз — внутри неё).
  - **Журнал ушей** `<данные>/ears/<дата>.jsonl` (`EarsJournal`): на каждую фразу — движок, длина, первые слова (мс),
    дочитывание (мс), число символов и промежуточных текстов; ни слов, ни звука. По нему «Уши»
    сравнивают GigaAM и T-one за неделю.
  - **Проверка без микрофона:** `Vera --hear <файл.wav> [--engine gigaam|tone]` — запись идёт через те же уши
    кусками по 100 мс; печатаются промежуточный текст с моментом появления, фраза и время дочитывания.
  - **Голос (речь Веры) — Silero TTS, голос baya, в коробке**: свой Python (копия сборочного CPython, не Hermes'), torch и
    модель v5_ru в `Vera03.app/Contents/Resources/mouth`; пакеты и sha256 модели — в `ears.lock.json` → `mouth`,
    сборка — `scripts/build-mouth.sh` (~1 ГБ). Рабочий процесс `scripts/mouth-worker.py` живёт всё время работы Веры
    (`python -I`, своё окружение): предложение внутрь, звук наружу; следующее синтезируется, пока звучит текущее.
    Скорость — 0,8–1,5 (по умолчанию 1,05) без изменения высоты (`AVAudioUnitTimePitch`), ползунком на «Голосе».
    **Текст ответа появляется вместе с голосом**: пока ответ озвучивается, в разговоре видно только уже сказанное
    (`VoiceModel.revealed`), после — весь текст с разметкой. Без рта в сборке — системный голос macOS.
    Проверка: `Vera --mouth-check "<текст>"`.
  - **Голос Мака без Python** — тот же Swift-голос, что у iPhone (`SileroVoice`: ONNX из `scripts/build-mouth-ios.sh`,
    в коробке `Resources/voice`, на onnxruntime ушей): загрузка ~0,3 с вместо 5–10 с у воркера, звук тот же. Python-рот
    остаётся запасным (без файлов ONNX) и пока нужен Smart Turn; на плитке «Ответ · голос» — «без Python» / «Python».
  - **Тот же голос на iPhone** — Silero baya без Python: `scripts/build-mouth-ios.sh` берёт `v5_ru.pt` из сборки рта,
    пересобирает его сети обычным PyTorch (`scripts/mouth-ios/silero_eager.py`: TorchScript сам в ONNX не выгружается)
    и выгружает `silero-encoder.onnx` (длительности, высота тона, кодировщик), `silero-decoder.onnx` (декодер, мел,
    вокодер и ISTFT — на выходе звук 48 кГц) и `silero-homo.onnx` (BERT омографов), плюс данные текстовой части.
    Перед выгрузкой звук ONNX сверяется с оригиналом (расхождение ~1e-4). Текстовая часть — построчный перенос
    Python Silero на Swift (`app/Sources/SileroVoice`: подготовка текста, омографы, n-граммный расстановщик ударений и
    ё, токенизатор BERT), сети идут через C API onnxruntime (`app/Sources/COnnx`: на Маке — dylib из коробки, на
    телефоне — его фреймворк). Тесты `SileroVoiceTests` сверяют ids с эталоном оригинала на 35 фразах и звук целиком.
    На телефоне — `PhoneSilero` в `Voice.swift`; системный голос iOS — запасной и по выбору в «Настройках».
    Проверка на телефоне/симуляторе: запуск с `--say "<текст>"` (журнал `VERA-VOICE`, файл `tmp/vera-say.wav`).
  - **VAD и распознавание параллельны**: звук идёт из микрофона и в VAD, и в распознавание; VAD только подаёт сигнал
    «фраза началась / закончилась» (пунктир VAD ⇢ Распознавание на доске).
  - Ответ озвучивается по предложениям, пока агент ещё пишет (`SpeechChunker`, рот Silero); заговорил
    поверх — озвучка стоп + `session.interrupt`. `voice.record` Hermes не используется: он открывал бы микрофон в
    процессе шлюза.
  - **Кто говорит — CAM++ (3D-Speaker), «определитель твоего голоса»: в коробке, но выключен** (`EarsSession.identifiesSpeakers`,
    решение владельца 2026-11-22): звук к нему не идёт, линии на схеме нет, карточка в анализаторах тусклая. Когда включим —
    отпечаток фразы против книги голосов `<данные>/voices.json` (порог 0,55 из Веры 2), «запомнить мой голос» — три фразы,
    Hermes получает пометку `[голос не узнан]` / `[говорит: имя]`, только если говоришь не ты (поля в шлюзе нет — вопрос
    к ядру в AGENTS.md).

### Где наш функционал

Свои возможности добавляем **плагинами и скиллами Hermes**, как требует сам Hermes
(`~/.vera03/hermes/hermes-agent/AGENTS.md`: «extended through plugins and skills, not by growing the core»).
Исходники наших плагинов живут в `hermes-plugin/`, копируются в бандл и подключаются ссылкой
`<данные>/hermes/plugins/<имя>` автоматически при старте Веры. Ядро Hermes не правим — тогда обновление Hermes не затирает нашу работу
(см. [hermes-updates.md](hermes-updates.md)).

### iPhone-сенсор

Телефон — ещё один канал «Разговоров» со своей закреплённой сессией Hermes (`phone-session.json`), мозг тот же.
```
iPhone (приложение phone/) ──wss://<адрес туннеля>/phone──▶ Cloudflare-туннель владельца ──▶ 127.0.0.1:8765
   текст, голос (PCM 16 кГц)                                     PhoneGate (Вера) ─▶ PhoneModel ─▶ адаптер ─▶ шлюз
   ◀── хвост сессии, «думает», что услышали уши ─────────────────┘
```
- Протокол `PhoneWire`: JSON-кадры (`pair`, `hello`, `say`, `voiceBegin/End`, `interrupt` ↔ `paired`, `items`, `state`,
  `heard`, `problem`), голос — бинарные кадры Int16 16 кГц. Без `pair`/`hello` за 10 с соединение закрывается.
- Сопряжение: одноразовый код в QR на карточке «iPhone» (5 минут, 5 ошибок сжигают код) → телефону длинный токен
  (держит в Keychain), Вера хранит только его SHA-256.
- Уши и голос — на самом телефоне: живой разговор без кнопки (Silero VAD + GigaAM v3 через sherpa-onnx, собранную
  для iOS `scripts/build-ears-ios.sh`), на Мак уходит текст (`spoken`); ответ Hermes озвучивается по предложениям
  системным русским голосом iOS через тот же аудиодвижок с эхоподавлением — говорящего можно перебить (голос
  замолкает, Hermes получает `interrupt`). Piper не взят: в sherpa-onnx 2.0 нет фонемизатора espeak.
  Старый путь «звук на Мак» (`voiceBegin/End`, `VoiceNote` на Маке) остаётся запасным.
- Вопросы агента (approval/clarify) пока отвечаются на Маке; телефон видит, что агент ждёт.
- Сессия телефона создаётся с названием «iPhone»: Hermes отдаёт сессию по названию, с «Вера» телефон попал бы
  в разговор MacBook.
- Приложение `phone/Vera.xcodeproj` (SwiftUI, iOS 26; код в `phone/VeraPhone.swiftpm/Sources`, расширение `phone/VeraWidgets` — Live Activity в Dynamic Island и на экране блокировки) — для езды на байке и разговора, не чат. Главный экран
  «В дороге»: большое кольцо (слушаю · слышу · думает · говорит · пауза; лучи — громкость), последняя пара «ты / Вера»
  крупно, одна строка связи. Разговор включается сам; работает с погашенным экраном (фоновый звук `UIBackgroundModes`
  дописывает `phone-deploy.sh` и переподписывает — в формате пакета приложения этого ключа нет); кнопка гарнитуры —
  пауза или «стоп»; короткие звуковые метки вместо взгляда. В меню: урезанная схема (Сенсоры, Связь, Hermes из пульса
  сессии телефона), история с полем ввода, «экран не гаснет». Модели и фреймворки не в git — `scripts/phone-assets.sh`.
  Токен и адрес — в Keychain телефона. Разрешение на микрофон спрашивается до первого включения записи.

Пока Вера запущена, Мак не засыпает от простоя (`KeepAwake`: `ProcessInfo.beginActivity(.idleSystemSleepDisabled)`): шлюз,
cron и сенсоры живут на этом Маке. Экран гаснет как обычно; закрытая крышка на батарее — решение macOS.

## Хранилище

| Что | Где |
|---|---|
| Hermes (код, Python, зависимости) | `Vera03.app/Contents/Resources/hermes` — только чтение |
| Конфиг, ключи (`.env`), сессии, память, логи Hermes | `~/Library/Application Support/Vera03/hermes` |
| Журнал пульса | `~/Library/Application Support/Vera03/hermes/vera-pulse/<yyyy-MM-dd>.jsonl` |
| HOME процессов Hermes | `~/Library/Application Support/Vera03/home` |
| Рабочий Hermes владельца `~/.hermes` | не используется |

## Чего пока нет (следующие шаги)

- Собственные инструменты и скиллы Веры как плагины Hermes.
- Вход через OAuth (Nous Portal, подписки) в карточке провайдера — пока только провайдеры с ключом.
- Урезание пакета (браузер, управление компьютером) — отдельное решение по размеру.
- **Домашний канал (home channel) не продуман.** Hermes доставляет туда итоги cron и сообщения между платформами;
  без него Telegram при первом сообщении просит `/sethome`. Пока — стандарт Hermes: домашним ставится чат Telegram
  командой `/sethome` в боте. Идея на потом — наша надстройка-плагин, которая решает, куда доставить (Telegram,
  голос в комнате, доска) и нужно ли доставлять сейчас вообще (тишина ночью, не дублировать то, что уже сказано
  голосом). Как механика с явными правилами, без своей модели — решает по-прежнему Hermes.
